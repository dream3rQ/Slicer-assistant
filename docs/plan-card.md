# Карточка изменений (подтверждение плана)

Прежде чем что-то поменять в слайсере, ассистент показывает карточку с планом. Агент ждёт ответа
пользователя внутри вызова `apply_plan`, поэтому «Применить» не тратит лишний шаг LLM.
Отключается в настройках: «Показывать изменения перед применением» (`confirm_plan`). Это удобно
для пакетных прогонов на оценку. MCP-клиенты и панель параметров вызывают `apply_plan` напрямую, без карточки.

Карточка не появляется, если в плане нет изменений: все пункты «без изменений» и нет ошибок.

## Данные: событие `proposal` в `GET /api/events`

```json
{"type": "proposal", "data": {
  "id": "p_1a2b3c", "call_id": "...", "extruder": 0,
  "items": [
    {"id": "mode", "kind": "mode", "label": "Режим печати", "current": "cylindrical", "proposed": "classic",
     "unchanged": false, "reason": "плоская деталь", "options": [{"value": "classic", "label": "3D"}]},
    {"id": "material_id", "kind": "material", ...},
    {"id": "quality_type", "kind": "quality", ...},
    {"id": "settings.wall_line_count", "kind": "setting", "key": "wall_line_count",
     "label": "Количество линий стенки", "type": "int", "unit": null, "minimum": 0,
     "current": 2, "proposed": 6, "unchanged": false, "reason": "прочность зубьев",
     "warning": "предупреждение: ...", "error": "..."}
  ]}}
```

- `type`: int, float, bool, enum, str. По нему выбирается поле ввода в режиме «Изменить».
- `options` есть у режима, материала, профиля и enum-настроек. Значения — `value`, подписи — `label`.
- `unit`, `minimum`, `maximum`, `reason`, `warning`, `error` могут отсутствовать.
- `error` значит, что пункт не применится (например, нет такой настройки). Ассистент исправит это после применения.

После ответа приходит `proposal_closed`: `{"id", "action": "apply|revise|reject|cancel", "overrides", "skip", "text"}`.
Карточку без `proposal_closed` нужно считать открытой (это важно, если страницу перезагрузили).

## Ответ: `POST /api/proposal`

| Кнопка | Тело запроса | Что делает ассистент |
|---|---|---|
| Применить | `{"id", "action": "apply"}` | применяет план как есть и продолжает (нарезка, сохранение) |
| Изменить → Применить | `{"id", "action": "apply", "overrides": {"settings.wall_line_count": 8}, "skip": ["quality_type"]}` | применяет с правками; правки не отменяет и объясняет по фактическим значениям |
| Уточнить | `{"id", "action": "revise", "text": "почему не PETG?"}` | отвечает на вопрос или учитывает замечание и показывает новую карточку |
| Отклонить | `{"id", "action": "reject", "text": "необязательно"}` | ничего не применяет и не нарезает, ждёт указаний |

Сообщение, набранное в обычном поле ввода, пока карточка открыта, работает как «Уточнить».
Кнопка «Стоп» закрывает карточку с `action: "cancel"`.

Ошибки возвращаются как HTTP 409 `{"error": "..."}`: карточка уже закрыта или неизвестное действие.

## Состояния карточки (CSS-классы в web/style.css)

- `.proposal`: открыта. Пункт `.item`, без изменений `.item.same`, с ошибкой `.item.bad`.
- `.proposal.editing`: режим «Изменить». Видны чекбоксы `.use` и поля `.edit`, скрыто `.new`.
- `.proposal.sending`: ответ отправляется, кнопки неактивны.
- `.proposal.closed`: решение принято, итог в `.done`. После применения `.item.edited` — значение пользователя, `.item.skipped` — пункт пропущен.
